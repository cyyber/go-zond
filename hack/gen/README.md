# hack/gen — test fixture generator

This package regenerates fixture files the go-qrl test suite depends on. It
exists because the 64-byte address / 512-bit VM migration invalidated large
parts of the fixture surface, and hand-editing hundreds of files is not viable.

## Usage

```sh
# regenerate everything
go run ./hack/gen --target=all --out=.

# regenerate a single class of fixture
go run ./hack/gen --target=addresses

# list available generators
go run ./hack/gen --list
```

Output is always relative to `--out` (default: repository root). Generators
must be deterministic — running `go run ./hack/gen --target=all` twice in a
row must produce a zero-line `git diff`, and CI should enforce that.

## Layout

| File | Responsibility |
| --- | --- |
| `main.go` | CLI dispatcher (`--target`, `--list`, `--out`). |
| `common.go` | Shared helpers (deterministic seed, atomic file write). |
| `addresses.go` | Stable labelled accounts → `testdata/addresses.json`. |
| `blocks.go` | TODO — genesis + block RLP/JSON fixtures. |
| `transactions.go` | TODO — signed tx fixtures (Legacy / DynamicFee / access-list). |
| `receipts.go` | TODO — receipts with 64-byte log topics. |
| `abi_fixtures.go` | TODO — encoded calldata + event topic fixtures. |

The TODO generators intentionally return an error. `--target=all` must not pass
until every fixture class is implemented and a zero-line `git diff` proves that
regeneration is deterministic.

## Generator contract

Every generator satisfies this contract:

1. **Deterministic.** Same source, same output bytes. No wall-clock, no
   `rand.Intn`. Use `deterministicSeed(label)` or a seeded RNG keyed on a
   stable label.
2. **Side-effect free outside `--out`.** No touching global state, no writing
   anywhere else.
3. **Idempotent.** Re-running the generator overwrites outputs atomically
   (`.tmp` rename) and never appends.
4. **Self-describing.** Each output file either carries a `// generated by
   hack/gen — do not edit` banner or is paired with a fixture loader that
   names the generator responsible for it.

## Adding a new generator

1. Drop `hack/gen/<name>.go` with `generate<Name>(outDir string) error`.
2. Register it in the `generators` slice in `main.go`.
3. Write outputs via `writeFile(outDir, relPath, payload)` so callers get
   atomic replacement for free.
4. Log a single line per output via `reportGenerated("<kind>", relPath)`.
5. Extend `README.md` with the new file row.
6. Add a unit test under `hack/gen/*_test.go` that runs the generator into
   `t.TempDir()` and asserts the payload hash.

## Consuming generated fixtures from tests

Prefer a small loader helper alongside the fixture:

```go
// core/testutil/accounts.go (example)
func LoadAccount(t *testing.T, label string) TestAccount { ... }
```

Tests call `testutil.LoadAccount(t, "alice")` instead of hardcoding addresses.
When the migration invalidates outputs again, only the generator changes.
